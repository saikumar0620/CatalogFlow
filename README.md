# CatalogFlow

A full-stack product inventory dashboard for managing a product catalog and tracking stock. CatalogFlow pairs a React interface with a FastAPI REST API and PostgreSQL persistence, with account-based access for inventory changes.

## Highlights

- Browse and search products by name or description.
- View inventory metrics: product count, total units, estimated stock value, and low-stock items (three units or fewer).
- Create, edit, and delete products after signing in.
- Adjust stock one unit at a time, with server-side protection against negative stock.
- Filter and paginate product listings through the API, with configurable sorting.
- Register and sign in with email and password; access tokens are refreshed through rotating refresh tokens.
- Responsive inventory interface with loading placeholders, connection status, confirmation prompts, and toast feedback.
- Interactive API reference generated by FastAPI at `/docs`.

- A reachable PostgreSQL database

## Getting started

### 1. Configure the backend

From the repository root, create `backend/.env` based on `backend/.env.example`:

```env
DATABASE_URL=postgresql://user:password@host/dbname?sslmode=require
JWT_SECRET_KEY=replace-with-a-long-random-secret
JWT_EXPIRE_SECONDS=3600
```

Use your PostgreSQL connection string and replace the example JWT secret with a secure random value. The application loads environment variables from `backend/.env` (and also checks for a root `.env`).

Schema creation and startup DDL adjustments are opt-in. Set `AUTO_MIGRATE=true` in the backend environment to enable them when starting the API. Otherwise, provision the database schema separately before use.

### 2. Start the API

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
uvicorn main:app --reload
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

The API runs at `http://127.0.0.1:8000`. Visit `http://127.0.0.1:8000/docs` for the interactive Swagger UI.

### 3. Start the frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the URL printed by Vite, usually `http://localhost:5173`. The Vite development server proxies `/api` requests to `http://127.0.0.1:8000` by default.

## Environment variables

### Backend

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string (required) |
| `JWT_SECRET_KEY` | Secret used to sign and validate tokens (required) |
| `JWT_EXPIRE_SECONDS` | Access token lifetime in seconds; defaults to 900 in code |
| `JWT_REFRESH_EXPIRE_SECONDS` | Refresh token lifetime in seconds; defaults to 604800 |
| `AUTO_MIGRATE` | Set to `true` to run schema creation and startup DDL adjustments |

### Frontend

| Variable | Purpose |
| --- | --- |
| `VITE_API_URL` | API base path or URL; defaults to `/api` |
| `VITE_API_PROXY_TARGET` | Local backend target for Vite's `/api` proxy; defaults to `http://127.0.0.1:8000` |

See `backend/.env.example` and `frontend/.env.example` for starter configuration.

## API overview

| Method | Endpoint | Description | Access |
| --- | --- | --- | --- |
| `GET` | `/` | Health status | Public |
| `POST` | `/auth/register` | Create an account | Public |
| `POST` | `/auth/login` | Sign in and issue tokens | Public |
| `POST` | `/auth/refresh` | Rotate a refresh token | Public, refresh token required |
| `POST` | `/auth/logout` | Revoke a refresh token | Public, refresh token required |
| `GET` | `/auth/me` | Get the signed-in user | Bearer token |
| `GET` | `/products` | List and filter products | Public |
| `GET` | `/product/{id}` | Get one product | Public |
| `POST` | `/product` | Create a product | Bearer token |
| `PUT` | `/product?id={id}` | Update a product | Bearer token |
| `DELETE` | `/product/{id}` | Delete a product | Bearer token |
| `PATCH` | `/product/{id}/stock` | Adjust product quantity | Bearer token |

`GET /products` accepts `search`, `min_price`, `max_price`, `in_stock`, `sort_by`, `order`, `limit`, and `offset` query parameters. It returns the total matching count in the `X-Total-Count` response header.

## Product data

Products contain a name, description, unit price, and quantity. The API validates non-negative prices and quantities, limits names to 120 characters and descriptions to 240 characters, and stores prices with two decimal places.
